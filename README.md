# AutoTelegramHorseZpBot-HorseZPBot# Telegram Scheduler / Auto-Poster

Полноценное локальное web-приложение для Windows, Linux и macOS, которое управляет пользовательским Telegram-аккаунтом через Telethon. Список чатов загружается из Telegram, а назначения для ПЧ и ПБ вы выбираете сами.

Это не бот-токен и не облачный сервис: Telegram-сессия, база SQLite и журнал хранятся локально в `data/`. Frontend обращается только к локальному API; Telegram API доступен исключительно через backend.

## Возможности

- Phone Login, 2FA и настоящий одноразовый Telegram QR Login;
- до трёх независимых Telegram-аккаунтов: отдельные сессии, чаты, ПЧ/ПБ, сообщения, логи и Gemini-настройки;
- сохранение и повторное использование сессии Telethon;
- импорт всех диалогов аккаунта без пересоздания существующего списка;
- автоматическая загрузка всех доступных Telegram-чатов после авторизации и ручное управление назначениями;
- отдельные списки ПЧ и ПБ, при этом одна подходящая группа может быть в обоих;
- снимок ПЧ на 6 групп и ПБ на 12 групп (значения меняются в Settings) с равномерным распределением;
- защита от повтора: ПЧ не повторяется в одном чате раньше 6 часов, ПБ — раньше 12 часов;
- независимые scheduler ПЧ и ПБ, с задержкой между группами по умолчанию 3600 секунд;
- сохранённые записи каждой доставки, исключающие повторную отправку уже отмеченной как `SENT` после перезапуска;
- реальная отправка через Telegram, сохранение `message_id`, проверка существования и удаление по таймеру для ПЧ/ПБ; сообщения Фермы и Gemini остаются в чате;
- ограниченные retry удаления и штатный статус `ALREADY_DELETED`;
- SQLite recovery scheduler и delete-задач, SSE live logs, тёмная/светлая тема;
- понятный вывод в терминал: каждая реальная отправка, удаление, ошибка и регулярный отчёт в периоды простоя;
- опциональный Gemini Assistant: отвечает от имени выбранного Telegram-аккаунта только в группах, которые вы явно включили;
- короткий автоответ: на точные сообщения «ом», «оч» или «об» отвечает реплаем «Вкрасти»: не чаще одного раза в минуту на аккаунт и одного раза в час одному пользователю;
- graceful shutdown для `SIGINT`/`SIGTERM`, который не сбрасывает незавершённый план.

## Быстрый запуск на Linux и macOS

Нужен Python 3.11–3.13. Для Linux также установите пакет виртуальных окружений для выбранного Python (например, `python3-venv`). На момент разработки Telethon не был подтверждён для Python 3.14; выберите Python 3.13, если установка зависимостей на 3.14 не проходит.

```bash
git clone <your-repository-url> telegram-scheduler
cd telegram-scheduler
./install.sh
cp .env.example .env
open -e .env
./start.sh
```

Откройте `http://127.0.0.1:8000`. `install.sh` создаёт `.venv`; `start.sh` запускает приложение в фоне. Для интерактивного запуска, где все реальные события сразу видны в терминале, используйте:

```bash
source .venv/bin/activate
python -m app
```

После запуска в фоне те же сообщения видны командой `tail -f data/server.log`.

## Быстрый запуск на Windows

Установите Python 3.11–3.13 с официального сайта и отметьте опцию добавления Python в `PATH`. В PowerShell из каталога проекта выполните:

```powershell
.\install.ps1
Copy-Item .env.example .env
notepad .env
.\start.ps1
```

Откройте `http://127.0.0.1:8000`. Для остановки и перезапуска используйте `.\stop.ps1` и `.\restart.ps1`. Журналы находятся в `data\server.log` и `data\server-error.log`.

## Telegram API и первая авторизация

1. Откройте [my.telegram.org/apps](https://my.telegram.org/apps), создайте приложение и скопируйте `api_id` и `api_hash` в `.env`.
2. Запустите приложение и откройте **Авторизация**.
3. Либо введите номер, код из Telegram и, если нужно, пароль 2FA, либо нажмите **Создать QR** и отсканируйте настоящий сгенерированный Telegram токен в мобильном клиенте.
4. После успеха сессия появится как `data/telegram.session`. Она не должна попадать в Git, резервные копии или логи.
5. Откройте **Chats**: после авторизации список диалогов загрузится автоматически. Включите нужные чаты для ПЧ, ПБ или обоих списков.

## До трёх Telegram-аккаунтов

В верхней панели выберите аккаунт или нажмите **+ Аккаунт**. Для каждого нового аккаунта пройдите Phone Login или QR Login отдельно. Приложение хранит сессии раздельно: для первого аккаунта — `data/telegram.session`, для следующих — `data/telegram-account-2.session` и `data/telegram-account-3.session`.

В выбранном аккаунте показываются только его чаты, история сообщений, состояние ПЧ/ПБ и журналы. Один и тот же Telegram Chat ID можно использовать разными аккаунтами, но их рассылки и планы не пересекаются.

## Ручной список групп

Telegram используется для подтверждения введённого Chat ID и получения названия. После добавления вы сами включаете переключатель ПЧ, ПБ или оба. Удаление архивирует запись: она исчезает из рабочего списка, но история отправок остаётся в базе.

## Ферма

На странице **Ферма** выберите один чат, укажите текст и включите расписание. Сообщение отправляется сразу, затем повторяется каждые 3 часа 58 минут. Сообщения Фермы не удаляются автоматически. Настройка и время следующей отправки сохраняются в SQLite и восстанавливаются после перезапуска.

## Рассылки и удаление

На странице **ПЧ** или **ПБ** сохраните текст и нажмите Start. На этот запуск создаётся стабильный снимок групп: изменения назначений во время выполнения сохраняются, но применятся только на следующем цикле. После последней группы создаётся новый снимок ручного списка. ПЧ и ПБ запускаются и останавливаются независимо.

Между группами действует задержка из Settings (по умолчанию час). Независимо от изменения количества групп repeat guard не позволит ПЧ повториться в том же чате раньше чем через 6 часов, а ПБ — раньше чем через 12 часов. В Logs фиксируются начало группы, завершение цикла и точное ожидание repeat guard.

Для сообщений ПЧ, ПБ и ручной отправки сохраняется Telegram `message_id` и создаётся delete task. В установленное время задача:

1. читает сообщение через Telegram API;
2. удаляет его, если оно существует (`DELETED`);
3. отмечает `ALREADY_DELETED`, если оно уже отсутствует;
4. при временной ошибке повторяет действие не более `MAX_DELETE_RETRIES` раз.

Сообщения Фермы и ответы Gemini сохраняются в Messages, но delete task для них не создаётся. При обновлении приложения старые задачи удаления для этих двух типов также отменяются.

## Gemini Assistant

Gemini выключен по умолчанию. Чтобы подключить его:

1. Создайте Gemini API key в Google AI Studio и внесите его в `GEMINI_API_KEY` файла `.env`.
2. Перезапустите приложение и выберите нужный Telegram-аккаунт.
3. В **Settings → Gemini Assistant** включите автоответы, выберите модель и сохраните инструкцию.
4. В **Chats** включите переключатель **Gemini** только у тех групп, где автоответ действительно разрешён.

Ассистент обрабатывает только новые входящие текстовые сообщения в явно отмеченных группах. На обычные сообщения он не отвечает: отвечает при упоминании, ответе на своё сообщение или при явной необходимости поддержки. Для неадресованных сообщений действует пауза между проактивными ответами, а перед каждой отправкой выдерживается естественная задержка набора. Контекст хранится раздельно для пары «аккаунт + группа» и ограничен последними сообщениями. Ключ Gemini не пишется в SQLite и не появляется в Logs. Ответы отправляются через тот же реальный Telegram-клиент, сохраняются в Messages и Logs, но не добавляются в очередь удаления.

## Автоответ «ом / оч / об»

На странице **Chats** включите переключатель **ОМ/ОЧ/ОБ** у нужных групп выбранного аккаунта. Если кто-то напишет ровно `ом`, `оч` или `об` (без дополнительного текста), аккаунт отправит ответ **«Вкрасти»** как reply к этому сообщению. Есть два сохранённых лимита: максимум один такой ответ за 60 секунд для всего аккаунта и максимум один ответ одному Telegram-пользователю за 60 минут. Оба лимита действуют между всеми разрешёнными группами и не сбрасываются при перезапуске. Автоответы «Вкрасти» сохраняются в Messages и удаляются по обычному таймеру.

Если у этой же группы включён Gemini, для этих трёх точных триггеров приоритет остаётся у короткого автоответа: Gemini не создаёт второй ответ.

## Что видно в терминале

В интерактивном режиме после каждой отправки и удаления появляется строка с аккаунтом, Chat ID и Message ID. Если активных отправок и удалений нет, раз в `TERMINAL_IDLE_REPORT_SECONDS` (по умолчанию 60 секунд) выводится состояние ПЧ и ПБ каждого аккаунта. Это подтверждение, что процесс жив и ожидает следующую задачу.

## Скрипты и тесты

```bash
./stop.sh
./restart.sh
make test
make lint
```

Unit-тесты работают офлайн и проверяют хранилище, равномерное деление, snapshots, recovery и delete flow. Реальные Phone/QR/2FA сценарии требуют принадлежащего вам Telegram тестового аккаунта и поэтому запускаются как ручная интеграционная проверка: приложение принципиально не подменяет их фиктивными ответами.
